## Document engine pooling + Snowflake session resilience (framework 0.4.11)

- **Intent:** Document the framework 0.4.11 database changes: the new per-connection `pool` config
  block (which replaces a hardcoded `pool_pre_ping=True`) and the Snowflake fix that stops
  long-running processes dying ~4h in with `390114: Authentication token has expired`.

- **Changed:**
  - `database/db-config.md` — two new sections. **Connection Pooling** documents the `pool` block
    with a key→SQLAlchemy-kwarg table, why the keys are unprefixed, and the warning that
    `size`/`max_overflow` are rejected by StaticPool/NullPool (so don't set them on sqlite
    `':memory:'`). **Snowflake** is a new first-class section — the connection shape
    (`account`/`warehouse`/`role`, key-pair auth) plus "Long-running processes and the 4-hour
    token", which explains both layers of the fix and how to override them. Also softened the older
    "if you were to use a 3rd party dialect like snowflake-sqlalchemy…" line, which read as though
    snowflake needed a `url` workaround; it is a supported dialect and now points at the new
    section.
  - `epologue/changelog/0.4.md` — new §0.4.11 (newest-first, above 0.4.10) covering both features,
    with the one behavior change (async engines gain pre-ping) called out explicitly along with its
    opt-out.
  - `epologue/release-notes.md` — one bullet appended to the 0.4 list.
  - No upgrade guide entry: the change is additive and requires no app-author action, so
    `upgrade/from-0.3-to-0.4.md` is untouched.
