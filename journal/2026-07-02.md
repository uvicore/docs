## Document View Composers (new `http/web/view-composers.md`)

- **Intent:** View composers were an undocumented feature (only referenced in `deeper/ioc.md`,
  `provider.md`, and a dead link in `web/templating.md`). Wrote a full Web-section page, modelled on
  the user's real composer + Laravel's view composers (the original inspiration).
- **Verified against source how composers actually work:**
  - Decorator `@uvicore.composer()` (`framework/uvicore/foundation/decorators/composer.py`),
    `singleton=False`, binds `object_type='composer'`.
  - Matched + merged in `response.View()` (`framework/uvicore/http/response.py:73-114`): the view
    name has its extension stripped (`name.split('.')[0]`), patterns are `re.search` **regexes**
    (`*` alone → all views), multiple composers can match, matches are cached per view. The composer
    is instantiated per render with 6 positional args (`request, name, context, status_code,
    headers, media_type`) and its returned dict is merged via `context.defaults(...)` — **the
    controller/view wins** on key conflicts.
  - Registration: `register_http_view_composers(module, views)` (string | list | dict form, plus
    `append=`, and `views=None` deletes) — `framework/uvicore/http/package/registers.py:66`; each
    package's `web.view_composers` is deep-merged into `uvicore.config.uvicore.http.view_composers`
    in `http/package/bootstrap.py:630-657`. Gated by the `views` registers flag.
  - CLI generator `./uvicore gen composer <name>` → `http/composers/` (folder from
    `package.py:folder_path('view_composers')`).
- **Key finding surfaced to the user:** the user's sample provider uses the **pre-0.4** short
  helpers (`self.composers()`, `self.views()`, `self.public()`, `self.assets()`) which no longer
  exist (commented out in `contracts/provider.py:65,70`); the composer *class* itself is unchanged.
  Documented only the current `register_http_*` API. Also flagged that the composer **stub**
  (`http/commands/stubs/composer.py`) and **generator hint** (`generators.py:118`) still print the
  stale `self.composer(...)`/`self.composers(...)` form — a framework fix, not a docs fix.
- **Changed:** new `docs/http/web/view-composers.md`; `mkdocs.yml` (Web nav after `views.md`);
  `web/templating.md` (repointed dead `../../deeper/templating.md` composer link to the new page);
  `web/index.md` ("Reading This Section" list, added as #7).
- **Validated:** `poetry run mkdocs build` exits 0; page emits, all cross-links resolve, no
  absolute/unrecognized-link lines.
